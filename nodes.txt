
- Attach a **label (`_slb_dns`)** to the scraped metric

Great question! In Kubernetes, understanding the **Control Plane** and **Data Plane** is super important for grasping how the whole system works. Let me break it down simply, like a real-world analogy:

---

## ⚙️ What is the Control Plane?

> The **Control Plane** is the **"brain"** of the Kubernetes cluster.  
It makes all decisions about the cluster.

It manages:
- **What** runs
- **Where** it runs
- **When** to scale
- **What to do** when something fails

### ✨ Key Components of the Control Plane:

| Component | Role |
|----------|------|
| `kube-apiserver` | Front door to the cluster (accepts all `kubectl` commands, API requests) |
| `etcd` | Key-value store for all cluster data (like a database) |
| `kube-scheduler` | Decides which node runs which Pod |
| `kube-controller-manager` | Handles health, replication, etc. |
| `cloud-controller-manager` (optional) | Integrates with cloud-specific stuff like AWS LoadBalancers |

📍 These components usually run on the **master node**.

---

## 📦 What is the Data Plane?

> The **Data Plane** is the **"worker"** layer — where your actual **application workloads (Pods)** run.

It’s made up of the **Worker Nodes** and:

### 🧱 Components on Each Worker Node:

| Component | Role |
|----------|------|
| `kubelet` | Talks to the control plane and ensures containers are running |
| `container runtime` | Actually runs containers (like Docker, containerd) |
| `kube-proxy` | Manages networking to make communication between Pods/services work |

---

## 🧠 vs 🏗️ Summary:

| Aspect         | Control Plane                  | Data Plane                |
|----------------|-------------------------------|---------------------------|
| Role           | Brains of the cluster          | Muscles (executes the workload) |
| Runs On        | Master Nodes                   | Worker Nodes              |
| Key Processes  | API Server, etcd, Scheduler    | kubelet, kube-proxy, container runtime |
| Handles        | Cluster decisions, scheduling  | Running Pods & containers |

---

### 🧪 Real-life Example:

You run:
```bash
kubectl apply -f my-app.yaml
```

- The **Control Plane** sees your request, schedules a Pod on the best node.
- The **Data Plane (worker node)** pulls the image and runs your app in a container.
- `kubelet` keeps it healthy, `kube-proxy` makes networking work.
